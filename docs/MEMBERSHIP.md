# 成员申请与只读权限

## 流程

```text
访客打开 /apply
→ 填用户名、密码、申请说明
→ 进入 pending 申请队列
→ 管理员在 /requests 审批
→ 通过后创建 reader 账号
→ 申请人用申请时的用户名/密码登录
→ 进入成员只读空间
```

管理员审批页：

```text
/admin → 注册申请
```

## 角色

### admin

完整管理权限：页面、模块、知识库、素材库、设置、AI。

### reader

只读：

- 公开页面
- `visibility = members` 的知识库条目
- 公开页面里已经引用的图片

不能：

- 编辑页面 / 上传 / 删除
- 访问管理员知识库、草稿、未引用素材
- 访问 `/api/bootstrap`、`/api/kb`、`/api/assets` 等管理接口
- 使用管理员 AI
- 管理用户或审批申请

## 知识库可见范围

成员只能看到：

```text
status = published
```

草稿、待审、归档条目不可见。  
**所有已发布条目都会对成员可见**，所以内部内容不要发布。

## 成员素材库

只显示：

- 公开页面 blocks 里引用的图片
- 不显示未引用文件
- 不显示站点 Logo、模块图标、管理用素材

## 聊天室

- 只有 admin 和已审批 reader 能进入
- 所有成员共用一个聊天室
- 管理员也可以发言
- 前端每 4 秒轮询一次
- 单条最多 1000 字，每用户每分钟最多 10 条

## 信箱

- 成员可以向管理员发送建议
- 管理员在「信箱」查看未读/全部
- 单条最多 3000 字，每用户每小时最多 5 条
- 目前只支持单向建议，不支持管理员回复

## 邀请码

管理员在「邀请码」页：

- 点一次生成 10 条
- 每个邀请码一次性使用
- 使用过的邀请码显示删除线
- 最多保留 50 条可见邀请码
- 超过 50 条时优先隐藏最近使用过的邀请码
- 如果未使用码仍然超标，删除最旧的未使用码

申请人可以在 `/apply` 填邀请码：

```text
有有效邀请码 → 立即创建 reader 账号并激活
没有邀请码 → 进入 pending 审批队列
```

## 防刷

- 公开申请页有蜜罐字段
- 同一 IP 3 次/小时
- 全站 50 条申请/24 小时
- 密码使用 scrypt
- 申请写入 `registration_requests`，不直接创建账号
- 管理员审批后才创建用户
- 邀请码一次性，验证后立即作废

## 当前没有做

- 邮件验证（没有配置 SMTP）
- Turnstile / 图形验证码（需要申请站点 key）
- 自动通知申请人（需要邮件/短信）
- 封禁/删除成员的管理 UI
- 私密模块对成员开放

## 测试

```text
1. /apply 提交申请
2. 管理员 /requests 看到 pending
3. 审批通过
4. 申请人登录 → 进入只读成员页
5. 成员看不到 admin 可见知识库
6. 成员 /api/kb、/api/assets、/api/bootstrap 返回 403
7. 成员 /kb、/assets 正常
8. 公开页面图片可用；未引用图片 /api/public/assets 返回 404
```
